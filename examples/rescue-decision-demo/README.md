# Synthetic decision replay

Open [replay.html](replay.html) directly in a browser. It is a self-contained,
offline **recorded results viewer** for three existing synthetic software fixtures.
Selecting a case does not execute Python. Source links work when the repository
files remain alongside the viewer; the embedded inputs and outputs also work
when the HTML is copied by itself. No server, network or installation is needed.

The examples make three software checks inspectable:

- A protein increase does not override a functional-benefit interval below the
  illustrative worthwhile-benefit threshold: `WORTHWHILE_BENEFIT_RULED_OUT`.
- Improved normal-survivor fraction does not override a failed death bound and
  detected selection: `DO_NOT_ADVANCE`.
- Unqualified exposure measurement prevents biological interpretation:
  `TECHNICALLY_INDETERMINATE`.

These are the existing frozen-case materializations identified in
[demo-receipt.json](demo-receipt.json), not new independent validation cases.
The intervals, counts, thresholds and qualification records are synthetic input
fixtures. The program does not fit those intervals from the counts or establish
that the referenced work occurred. No drug results, rescue, clinical benefit,
causal mechanism or treatment recommendation is demonstrated. See the
[decision contract and input schema](../../analysis/rescue_decision/README.md).

**Illustrative rule inputs, not a fitted laboratory dataset:** the counts and
intervals were not generated by one statistical fit. The same counts appear
across fixtures while supplied intervals differ. Do not infer effect sizes or
statistical consistency from these fixtures.

## Replay and verify

From the **repository root** (`repo/` in the parent workspace), using Python 3.9+
and the standard library:

```sh
python3 -B -S examples/rescue-decision-demo/replay.py --verify
```

Verification checks exact input, implementation, schema-description, generator
and original-receipt hashes, launches the real
[`decision.py`](../../analysis/rescue_decision/decision.py) for all three fixtures,
compares their exact captured stdout and checks the complete HTML against the
receipts and renderer. It does not write files. A changed source, altered receipt,
wrong output (even with a recomputed output hash) or altered HTML fails.

To deliberately regenerate the two generated files after reviewing a source
change:

```sh
python3 -B -S examples/rescue-decision-demo/replay.py --generate
python3 -B -S examples/rescue-decision-demo/replay.py --verify
```

`--generate` invokes the actual Python CLI, checks the three specified decisions
and empty replication-candidate lists, then replaces `replay-results.json` and
`replay.html`. It does not edit the fixtures or decision implementation. Its
JavaScript only selects and displays recorded fields; it contains no decision
rules. Generation is deterministic for unchanged sources and CLI output. Each
file is replaced atomically; verification detects a pair interrupted between
the two replacements.

[replay-results.json](replay-results.json) records repository-relative paths and
rerun commands, SHA256 of exact input and implementation bytes, complete original
input text, complete captured stdout, its SHA256 and the process exit code.
No absolute workstation paths are required. These local consistency receipts
are not signed attestations, independent validation or proof against coordinated
changes to both code and receipts. A browser displays the recorded hashes; the
Python verification command performs the checks. Exit 0 from `decision.py` means
valid input, not a favourable biological finding.

Run the bounded replay tests (including source and output tampering in temporary
copies, without changing the original fixtures):

```sh
python3 -B -m unittest discover -s examples/rescue-decision-demo -p test_replay.py -v
```
